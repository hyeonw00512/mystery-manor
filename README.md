# 흑야 저택 — 실시간 추리 보드게임

Clue/Cluedo의 장르적 구조인 `용의자 + 장소 + 도구` 추리를 참고하되, 이름·디자인·문구·데이터를 독자적으로 만든 실시간 웹 보드게임입니다. 현재 Phase 1~11이 구현되어 있습니다.

## 현재 구현 기능

- React 19 + Vite + TypeScript 반응형 클라이언트
- Node.js + Express + Socket.IO 서버
- 6자리 방 코드, 코드 참가, `/room/:code` 초대 링크
- 방장, 3~6명 정원, 준비 상태, 중복 방지 캐릭터 선택
- 로비/게임 중 실시간 채팅
- 서버 전용 정답 생성 및 암호학적 난수 기반 카드 셔플
- 정답 3장을 제외한 카드의 균등 분배
- 공개 상태와 개인 상태 Socket 이벤트 분리
- `playerId + sessionToken + roomId + socketId` 분리 및 새로고침 재접속
- PC/태블릿/모바일 반응형 UI
- 9개 장소와 24개 이동 칸으로 구성된 데이터 기반 보드
- 연결 경로와 비밀 통로 데이터 및 서버 검증
- 캐릭터별 시작 위치와 실시간 플레이어 말 표시
- 마우스·터치 드래그, 휠 확대, 모바일 pinch zoom
- 모바일 보드·카드·기록·채팅 탭
- 서버에서 생성하는 주사위 결과
- 보드 연결 관계를 이용한 BFS 이동 가능 범위 계산
- 장소를 중간 경로로 통과하지 않는 이동 규칙
- 비밀 통로 설정을 반영한 이동 범위
- 이동 가능 칸 강조 및 클릭·터치 이동
- 서버 이동 검증, 장소 입장, 턴 종료와 다음 플레이어 전환
- 장소에서 `용의자 + 현재 장소 + 도구` 추리 제안
- 현재 플레이어 다음 순서부터 첫 카드 보유자 탐색
- 여러 후보 중 응답자가 공개할 카드 한 장을 선택하는 전용 모달
- 카드 내용은 추리자에게만 전달하고, 다른 플레이어에게는 공개 로그만 전송
- 아무도 카드를 보여주지 못한 경우의 공개 기록
- 재접속 후에도 응답 대기 상태와 자신이 확인한 카드 기록 복구
- 21장 전체를 분류한 개인 추리 노트
- 내 손패(`내 카드`)와 직접 공개받은 카드(`확인됨`)의 자동 메모
- `미정 / 가능성 낮음 / 정답 후보 / 제외` 수동 판단과 카드별 160자 개인 메모
- 메모 수정은 해당 플레이어의 비공개 상태만 갱신
- 현재 차례의 최종 추리 선언과 서버 전용 정답 판정
- 오답 시 조사 행동 탈락, 카드 공개 역할 유지
- 정답 성공 또는 전원 탈락 시 정답·승자·모든 손패를 게임 종료 화면에서 공개
- `playerId + sessionToken` 기반 새로고침·일시 단절 재접속 복구
- 5분 재접속 유예 상태와 실시간 참가자 목록 표시
- 방장 전용 오프라인 현재 턴·카드 응답 건너뛰기
- 오프라인 카드 응답자를 건너뛴 뒤 다음 카드 보유자 재탐색
- 재접속 시 최근 공개 채팅 기록 복구
- 방장이 재접속 대기 중이면 연결된 다른 플레이어가 오프라인 진행을 대행
- Socket 요청의 객체·문자열·불리언 형태를 서버에서 런타임 검증
- 모바일 전용 고정 하단 행동 바와 안전 영역 대응
- `내 위치` 보드 중심 맞춤, 작은 화면용 보드 도구 모음
- 보드·카드·노트·기록·채팅 탭에서 행동 영역 가림 방지
- 모바일 추리·카드 공개·최종 추리 모달의 하단 시트 UI
- 서버 확정 결과를 따른 주사위 정착·말 이동 애니메이션
- 추리 제안 배너, 비공개 카드 공개 플립, 사건 종결 스탬프 연출
- 브라우저 Web Audio 기반의 짧은 효과음과 PC·모바일 음소거 토글
- `prefers-reduced-motion` 사용자 설정을 존중하는 모션 축소 처리

GitHub Actions 검증과 Render 단일 Web Service 배포 구성이 포함되어 있습니다. 배포 절차는 [docs/DEPLOY_RENDER.md](docs/DEPLOY_RENDER.md)를 참고합니다.

## 요구 환경과 실행

- Node.js 20 이상
- npm 10 이상 권장

```bash
npm install
npm run dev
```

브라우저에서 `http://localhost:5173`을 엽니다. 서버 상태 확인 주소는 `http://localhost:3001/api/health`입니다.

Vite 감시 기능 없이 배포와 같은 방식으로 한 주소에서 테스트하려면 `npm run build` 뒤 PowerShell에서 `$env:NODE_ENV="production"; $env:PORT="3001"; npm start`를 실행하고 `http://localhost:3001`을 엽니다.

다른 PC/모바일에서 접속하려면 서버를 실행한 PC의 LAN IP를 사용합니다. `server/.env.example`과 `client/.env.example`을 각각 같은 폴더의 `.env`로 복사한 뒤 `CLIENT_URL`과 `VITE_SERVER_URL`을 실제 접속 주소로 바꿉니다.

인터넷 배포 시에는 HTTPS를 사용해야 합니다. Render 단일 서비스 배포에서는 프런트와 서버가 같은 주소를 사용하므로 `VITE_SERVER_URL` 설정이 필요 없습니다. 커스텀 도메인을 연결하면 `CLIENT_URL`만 실제 `https://` 주소로 설정합니다.

## 3인 수동 테스트

1. 일반 창에서 닉네임을 입력하고 새 조사실을 만듭니다.
2. 방 코드를 복사해 시크릿 창과 모바일에서 각각 다른 닉네임으로 참가합니다.
3. 세 사용자가 서로 다른 캐릭터를 선택하고 모두 준비합니다.
4. 방장이 게임 시작을 누릅니다.
5. 각 브라우저에 서로 다른 개인 카드만 표시되는지 확인합니다.
6. 한 브라우저 개발자 도구의 Socket 메시지에서 `room:state`에 `solution`과 타인의 `cards`가 없는지 확인합니다.
7. 한 브라우저를 새로고침해 같은 플레이어로 복구되는지 확인합니다.
8. 시작된 게임에서 각 캐릭터 말이 서로 다른 시작 칸에 표시되는지 확인합니다.
9. PC에서 보드를 드래그하고 마우스 휠로 확대·축소합니다.
10. 모바일에서 한 손가락 드래그, 두 손가락 확대·축소와 하단 탭을 확인합니다.
11. 현재 플레이어만 주사위 버튼이 활성화되는지 확인합니다.
12. 주사위를 굴린 뒤 강조된 장소 또는 복도 칸을 선택해 모든 화면에서 말 위치가 함께 바뀌는지 확인합니다.
13. 장소에 도착하면 `ROOM_ACTION`, 복도에 멈추면 `END_TURN` 상태가 되는지 확인합니다.
14. 턴 종료 후 다음 플레이어에게 주사위 버튼이 넘어가는지 확인합니다.
15. 장소에 도착한 현재 플레이어가 `추리하기`를 누르고 용의자와 도구를 선택합니다.
16. 제안한 장소가 현재 위치로 자동 고정되는지 확인합니다.
17. 해당 카드가 있는 첫 번째 플레이어에게만 카드 선택 모달이 표시되는지 확인합니다.
18. 후보 카드가 여러 장이면 한 장만 선택할 수 있는지 확인합니다.
19. 선택된 카드 이름은 추리자 화면에만 나타나고 나머지 화면에는 공개자의 행동만 기록되는지 확인합니다.
20. 카드가 없는 조합에서는 모든 화면에 `아무도 해당 카드를 보여주지 못했습니다.`가 기록되는지 확인합니다.
21. PC 오른쪽 패널 또는 모바일 `노트` 탭에서 개인 추리 노트를 엽니다.
22. 내 손패가 `자동 · 내 카드`, 직접 공개받은 카드가 `자동 · 직접 확인`으로 표시되는지 확인합니다.
23. 자동 상태가 아닌 카드를 선택해 판단 상태와 개인 메모를 저장하고, 다른 브라우저에는 변동이 없는지 확인합니다.
24. 새로고침 후 개인 메모와 자동 기록이 같은 상태로 복구되는지 확인합니다.
25. 자신의 차례에 `최종 추리`를 눌러 용의자·장소·도구를 선택하고 확인 체크 후 선언합니다.
26. 일부러 틀린 조합을 선언한 플레이어가 이동·추리를 할 수 없지만, 이후 카드 공개 요청의 대상은 되는지 확인합니다.
27. 정답 조합을 선언하면 모든 화면에서 사건 기록 공개 화면이 열리고 정답, 승자, 각 플레이어의 손패가 보이는지 확인합니다.
28. 게임 중 한 브라우저를 새로고침하거나 네트워크를 잠시 끊어 참가 목록이 `재접속 대기`로 바뀌는지 확인합니다.
29. 같은 브라우저가 다시 연결되면 기존 손패·노트·위치로 복구되고 재접속 대기 표시가 사라지는지 확인합니다.
30. 오프라인 플레이어의 턴 또는 카드 응답이 멈춘 경우 방장에게만 `오프라인 건너뛰기`가 활성화되는지 확인합니다.
31. 오프라인 카드 응답자를 건너뛴 뒤 다음 카드 보유자에게만 카드 선택 모달이 표시되는지 확인합니다.
32. 채팅을 남긴 뒤 새로고침해 최근 채팅 기록이 복구되는지 확인합니다.
33. 방장이 오프라인일 때 다른 연결 플레이어가 오프라인 턴을 건너뛸 수 있고, 방장이 연결되어 있으면 해당 권한이 거부되는지 확인합니다.
34. 모바일 세로 화면에서 하단 행동 바가 보드·카드·채팅을 가리지 않고 주사위/추리/턴 종료를 실행할 수 있는지 확인합니다.
35. 보드에서 `내 위치`, `맞춤`, 확대·축소를 누르고 한 손가락 드래그와 두 손가락 확대·축소를 확인합니다.
36. 모바일에서 추리·카드 공개·최종 추리 모달이 화면 하단 시트로 열리고 버튼이 키보드·안전 영역에 가려지지 않는지 확인합니다.
37. 주사위를 굴렸을 때 서버가 확정한 값이 회전·정착 효과와 함께 표시되는지 확인합니다.
38. 이동 후 모든 화면에서 해당 말이 새 칸으로 부드럽게 이동하고, 추리 시 보드 상단에 공개 가능한 조합만 표시되는지 확인합니다.
39. 카드 공개를 받은 추리자에게만 카드 플립 연출과 효과음이 보이고 들리는지 확인합니다.
40. 게임 종료 때 사건 종결 화면과 해결 스탬프가 표시되며, 정답·손패 공개 규칙은 이전과 동일한지 확인합니다.
41. PC 우측 상단 또는 모바일 하단의 `♬/♩` 버튼으로 효과음을 켜고 끌 수 있는지 확인합니다.

## 구조

```text
mystery-manor/
├─ shared/                 공용 타입, 이벤트, 카드/캐릭터/규칙/보드 데이터
├─ server/
│  ├─ src/game/            방, 게임 초기화, 보드·이동·추리 검증 로직
│  ├─ src/socket/          인증된 Socket 이벤트 처리
│  └─ test/                카드 보안·분배·재접속 테스트
└─ client/
   └─ src/
      ├─ components/       로비, 보드, 플레이어, 기록, 채팅, 손패, 개인 추리 노트
      ├─ context/          Socket 및 상태 관리
      ├─ pages/            입장 및 방 화면
      └─ styles/           반응형 디자인
```

## 보안 경계

- `GameRoom.solution`은 서버 메모리에만 존재합니다.
- 공개 `room:state`에는 카드 수만 포함되고 카드 배열은 없습니다.
- 개인 손패는 해당 플레이어의 현재 `socketId`에만 `player:private`로 전송됩니다.
- 공개할 수 있는 후보 카드는 응답자의 `player:private` 상태에만 포함됩니다.
- 선택된 카드 내용은 `player:card-revealed` 이벤트로 추리자의 Socket에만 전송됩니다.
- 공개 상태와 게임 로그에는 누가 누구에게 한 장을 보여줬는지만 기록됩니다.
- 개인 추리 노트는 `player:private` 상태의 해당 플레이어 항목에만 포함되며 `room:state`에는 포함되지 않습니다.
- `game:make-accusation`의 정답 판정은 서버 메모리의 봉인된 정답으로만 수행됩니다.
- 정답과 전체 손패는 상태가 `GAME_OVER`가 된 뒤의 공개 `gameOver` 요약에만 포함됩니다.
- 연결 해제 시 플레이어는 삭제되지 않으며, 서버는 재접속 유예 시각을 공개 상태에만 표시합니다.
- `game:skip-disconnected`는 방장 세션, 오프라인 상태, 현재 턴 또는 카드 응답 상태를 서버에서 모두 검증합니다.
- 방장이 재접속 대기 중일 때만 다른 연결 플레이어가 `game:skip-disconnected`를 대행할 수 있습니다.
- 모든 클라이언트 명령은 서버에서 런타임 입력 형식을 확인한 뒤 게임 규칙 검증으로 전달됩니다.
- 모든 로비 변경과 게임 시작은 서버에서 플레이어 세션, 상태, 권한을 재검증합니다.
- 서버 메모리 방식이므로 서버 프로세스를 재시작하면 방은 사라집니다. DB/Redis 영속화는 후속 확장 지점입니다.
